# 开发计划

## 阶段 1：项目骨架

- 建立 C++/CMake 项目结构。
- 添加命令行启动入口。
- 添加修改项、配置、进程接口的基础模块。
- 状态：已完成。

## 阶段 2：进程附加

- 根据进程名查找目标游戏。
- 打开目标进程句柄。
- 显示附加状态和失败原因。
- 状态：基础版已完成，Windows 下使用 `OpenProcess`，非 Windows 环境保留可编译占位。

## 阶段 3：内存读写

- 封装安全的读取和写入函数。
- 对地址、进程状态和权限做检查。
- 避免直接散落调用系统 API。
- 状态：基础版已完成，统一入口为 `MemoryAccessor`。

## 阶段 4：修改项系统

- 每个修改项包含名称、说明、启用状态和执行逻辑。
- 支持启用、禁用和状态显示。
- 后续支持热键绑定。
- 状态：管理器基础版已完成，统一入口为 `Trainer`。当前已支持默认热键字段、配置覆盖、启用、禁用和切换命令。

## 阶段 5：界面

- 初期保留命令行，便于调试。
- 稳定后再选择 Win32、Qt 或 ImGui 图形界面。
- 状态：命令行调试界面增强中，已支持 `--help`、`--version`、`--list`、`--enable`、`--disable`、`--toggle`。

## 阶段 5.5：运行日志

- 记录启动、目标进程、附加失败、未知修改项等关键事件。
- 默认写入 `logs/fengling_trainer.log`。
- 状态：基础版已完成。

## 阶段 5.6：配置文件

- 支持从 INI 风格 `key=value` 文件读取目标进程、日志路径和修改项热键。
- 命令行参数优先级高于配置文件。
- 提供 `config/fengling_trainer.example.ini` 示例。
- 状态：基础版已完成。

## 阶段 5.7：游戏适配 Profile

- 支持从独立 Profile 文件读取游戏名、进程名、修改项地址、值类型和值。
- 支持 `--validate-profile` 打印和校验 Profile。
- 支持 `--dry-run` 预览启用修改项对应的内存写入，不触碰真实进程。
- 提供 `config/example-game.profile.ini` 示例。
- 状态：基础版已完成。

## 阶段 6：真实游戏适配

- 确定第一个离线单机目标游戏。
- 记录目标进程名和版本号。
- 建立地址、指针链或特征码的独立 Profile。
- 每个修改项先在测试程序或离线环境验证。
- 当前前置条件：Profile 解析和 dry-run 已完成，真实写入接入待补。

## 阶段 7：发布准备

- 增加版本号和构建产物目录。
- 增加基本错误日志。
- 编写使用说明和风险提示。
- 打包 Windows 可执行文件。
- 状态：版本号和基础日志已加入，打包流程待补。
